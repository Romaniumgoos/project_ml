# TrainKey: клавиатурный тренажёр с биометрическим ML-античитом и адаптивным профилированием

Учебный проект по курсу «Основы машинного обучения».

Тренажёр записывает, **когда нажата и отпущена каждая клавиша**. По этим таймингам решаются три задачи:

| Задача | Вопрос | Свои реализации | Бенчмарки (sklearn) |
|---|---|---|---|
| **Античит** | с какой вероятностью печатает скрипт/бот (P и 90% доверительный интервал)? | байесовская логистическая регрессия (аппроксимация Лапласа) + калибровка Платта, MLP (numpy, ручной backprop), BiGRU с вручную написанной GRU-ячейкой (PyTorch) | LogisticRegression, RandomForest, HistGradientBoosting |
| **Биометрия** | печатает владелец аккаунта или кто-то другой? | детектор Махаланобиса со shrinkage-ковариацией, Scaled Manhattan (numpy), сиамская BiGRU + triplet loss (PyTorch) | OneClassSVM, IsolationForest |
| **Профилирование** | какой у человека стиль печати и какие переходы между клавишами у него слабые? | k-means++ и GMM/EM (numpy), PCA через SVD, эмпирический Байес для биграмм | KMeans |

Метрики (ROC-AUC, EER, ARI, силуэт) и разбиения GroupKFold тоже написаны с нуля (`keyml/metrics.py`). В тестах они сверяются со sklearn.

## Быстрый старт

### Запуск сайта у себя в один клик

- **Windows:** двойной клик по `start.bat` в папке проекта.
- **macOS / Linux:** `start.command` (или `python3 run.py`).

Скрипт запускает сервер и сам открывает сайт в браузере (http://localhost:8000; если порт занят, берётся следующий). Остановить: закрыть окно или нажать Ctrl+C. Ссылки на режимы печатаются в окне:

- режим читера: `http://localhost:8000/?cheat=1`;
- режим отладки без лимита сессий: `http://localhost:8000/?debug=local`;
- выгрузка данных: `http://localhost:8000/api/admin/export?token=local-admin`.

**Что нужно для локального запуска:** только Python 3.9+. Никаких внешних сервисов и интернета: сервер написан на стандартной библиотеке Python (WSGI + SQLite), страница состоит из локальных HTML/JS/CSS без CDN и внешних шрифтов. numpy нужен лишь для онлайн-оценки вероятности читерства. Если его нет, `run.py` один раз попробует поставить его через pip, а при неудаче сайт запустится без этой оценки.

### Эксперименты и тесты

```bash
pip install -r requirements.txt

# эксперименты на синтетических пользователях (проверить, что всё работает)
python scripts/run_experiments.py --simulate 50

# эксперименты на реальных данных (выгрузка с сервера)
python scripts/export_data.py https://LOGIN.pythonanywhere.com ТОКЕН
python scripts/run_experiments.py --data data/real_attempts.jsonl

# тесты
python -m pytest -q tests
```

Если PyTorch не установлен, флаг `--no-torch` пропускает нейросетевые эксперименты, остальное работает.

### Где хранятся данные (SQLite)

- **База** — один файл `~/trainkey_data/keystrokes.db`, то есть **вне папки проекта**. Повторный `git clone`, `git pull` или удаление папки проекта её не трогают. Путь можно переопределить переменной `KT_DB`.
- **Переезд со старого места.** Если найдена база по старому пути `collector/data/keystrokes.db`, при первом запуске она один раз копируется в новое место.
- **Резервные копии.** Раз в сутки (`KT_BACKUP_HOURS`) сервер сам кладёт сжатую консистентную копию в `~/trainkey_data/backups/` и хранит 7 последних (`KT_BACKUP_KEEP`).
- **Ручные действия администратора:**
  - `/api/admin/backup?token=…` — сделать копию прямо сейчас;
  - `/api/admin/db?token=…` — скачать всю базу одним файлом;
  - `/api/admin/export?token=…` — выгрузка в `.jsonl` для экспериментов.
- **Режим журнала WAL:** чтение не блокирует запись.

## Как собрать датасет

### 1. Развернуть тренажёр в интернете (бесплатно, ~15 минут)

Вариант **PythonAnywhere** (бесплатный аккаунт, диск постоянный, SQLite там не теряется):

1. Зарегистрироваться на pythonanywhere.com, в Bash-консоли выполнить `git clone <ваш репозиторий>` (или загрузить файлы через вкладку Files).
2. Web → Add a new web app → Manual configuration → Python 3.10+.
3. В WSGI-файле (ссылка на странице Web) заменить содержимое на:
   ```python
   import os, sys
   os.environ["KT_ADMIN_TOKEN"] = "придумайте-длинный-секрет"
   os.environ["KT_DEBUG_TOKEN"] = "второй-секрет"          # режим отладки /?debug=...
   os.environ["KT_MAX_SESSIONS_PER_DAY"] = "3"
   sys.path.insert(0, "/home/ЛОГИН/project_ml")
   from collector.server import application
   ```
4. Static files: URL `/` → не нужно, сервер отдаёт статику сам. Нажать Reload.
5. Ссылка для участников: `https://ЛОГИН.pythonanywhere.com`.

База будет в `/home/ЛОГИН/trainkey_data/` (переменную `KT_DB` задавать не нужно).

Альтернатива на время сбора: запустить `start.bat` у себя и открыть доступ через `cloudflared tunnel --url http://localhost:8000`. Но тогда компьютер должен быть включён всё время сбора.

> Онлайн-античит на сервере использует numpy. На PythonAnywhere numpy уже установлен. Если numpy нет, сервер просто не показывает вероятность читерства, а данные собирает как обычно.

### 2. Протокол для участника

- **Анкета:** язык текстов, тип клавиатуры, слепая печать или нет, ведущая рука, часы за клавиатурой в день. Её ответы дают признаки для анализа кластеров и «истину» для проверки, совпадают ли кластеры с самооценкой.
- **Сессия (~5 минут), смешанный режим:**
  - **фиксированная фраза ×6:** полная панграмма «Съешь же ещё этих мягких французских булок, да выпей чаю.» со всеми 33 буквами (для английского — «The quick brown fox jumps over the lazy dog.»). На ней учится биометрия: одинаковый текст даёт сравнимые векторы таймингов;
  - **6 случайных заданий** по ~70 символов из ~240 самых частотных слов (`keyml/corpus.py`, `FREQ_WORDS`). Их нельзя заранее записать макросом, и каждая сессия даёт новые биграммы;
  - **со второй сессии** — персональное упражнение под слабые биграммы.
- **До 3 сессий в день.** Лимит считается по календарным суткам (полночь по Минску) и задаётся переменными `KT_MAX_SESSIONS_PER_DAY` и `KT_TZ_OFFSET_HOURS`. Таймера между сессиями нет. Для биометрии всё же важны сессии **в разные дни**: в один день человек печатает слишком одинаково, и оценка получится нечестной.
- **Режим отладки:** `/?debug=<KT_DEBUG_TOKEN>` снимает дневной лимит, сайт показывает фиолетовую плашку. Такие сессии не расходуют лимит, а их попытки помечаются `flags.debug = 1`. `run_experiments.py` по умолчанию их отбрасывает, флаг `--keep-debug` их оставляет. Без заданного токена режим выключен. Режим читера (`?cheat=1`) лимитом не ограничен.
- Участник получает код вида `ABCD-EF23`, который хранится в браузере. С ним можно продолжить с другого устройства.
- **Мотивация:** таблица лидеров, рост скорости по сессиям, отчёт о слабых переходах.

**Сколько нужно:** см. раздел «План сбора данных и обучения» ниже. Где искать участников: своя группа и поток, чаты других групп, знакомые. Попросите каждого переслать ссылку двум друзьям.

### 3. Реальные читерские данные (негативный класс)

Боты генерируются программно (`keyml/bots.py`, 7 типов), но реальные примеры ценнее. Попросите 5–10 добровольцев:

1. Открыть `…/?cheat=1`, выбрать тип читерства. Все попытки помечаются `mode=cheat`.
2. Запустить один из скриптов из `tools/cheat_scripts/` с разными параметрами: `autotype.ahk` (AutoHotkey) или `cheat_bot.py` (pynput, 8 режимов, включая запись и воспроизведение своей печати). Пошаговая инструкция по каждому типу — в `tools/cheat_scripts/README.md`.
3. Отдельный ценный тип — `other_person`: человек печатает под **чужим** кодом. Это тест биометрии.

Такие события браузер помечает `isTrusted=true`, то есть отличить их от человеческих можно только по таймингам. Ради этого и нужен ML. События, созданные JavaScript (`isTrusted=false`), сервер ловит простым правилом.

### 4. Этика и данные

- Согласие обязательно, иначе сервер не регистрирует участника. Имя не спрашивается, только псевдоним.
- Печатается только заданный текст, поэтому личной информации в записях нет.
- Тайминги нажатий относятся к биометрическим данным: в отчёте указать, что данные анонимны и используются только в учебных целях. Выгрузка доступна только по секретному токену.

### Формат данных

Каждая попытка (строка `.jsonl` / запись в SQLite):

```json
{"user_id": "ABCD-EF23", "session_no": 2, "kind": "calib|text|adaptive", "lang": "ru",
 "prompt": "...", "typed": "...", "mode": "normal|cheat", "cheat_type": null,
 "events": [["d", "KeyF", "а", 1532.4, 1], ["u", "KeyF", "а", 1621.0, 1], ...],
 "flags": {"blur": 0, "paste": 0, "user_meta": {...}}}
```

`events`: тип (`d` = keydown, `u` = keyup), физический код клавиши (`event.code`, не зависит от раскладки), символ, время в мс от показа задания (`performance.now()`), `isTrusted`.

## Открытые датасеты (когда своих участников мало)

Своих участников 5–10, поэтому основное обучение и доказательство того, что модель обучилась, делаются на открытых данных. Свои люди остаются **реальной проверкой**.

| Датасет | Что в нём | Для чего у нас |
|---|---|---|
| [CMU Keystroke Benchmark](https://roymaxion.github.io/projects/keystroke-benchmark/benchmark-data-set.html) (Killourhy & Maxion, DSN 2009, CC-BY-ND 2.0) | 51 человек × 8 сессий × 50 повторов пароля `.tie5Roanl` | биометрия на фиксированном тексте; сверка нашей реализации с опубликованными EER |
| [Aalto 136M Keystrokes](https://userinterfaces.aalto.fi/136Mkeystrokes/) (Dhakal et al., CHI 2018, некоммерческое использование с указанием авторов) | ~169 тыс. человек, по 15 английских предложений, время нажатия и отпускания каждой клавиши | класс «человек» для античита, кривая обучения, перестановочный тест, стили печати, средние тайминги биграмм |

```bash
python scripts/download_datasets.py                 # один раз: CMU (5 МБ) + Aalto (1.5 ГБ, не распаковывается)
python scripts/run_external.py                      # отчёт reports/external/external.md
python scripts/run_external.py --export-model       # + обучить итоговую модель для сайта
python scripts/export_data.py https://ЛОГИН.pythonanywhere.com ТОКЕН
python scripts/run_external.py --export-model --own data/real_attempts.jsonl   # + проверка на своих людях
```

`keyml/external.py` приводит оба датасета к формату проекта. У Aalto одно предложение одного участника считается одной попыткой. Берутся только участники с раскладкой QWERTY и физической клавиатурой: у AZERTY и QWERTZ JavaScript-код клавиши не совпадает с физической клавишей. CMU сразу даёт векторы H/DD/UD — такие же, как наша калибровочная фраза.

**Итоговая модель для сайта** (`--export-model`) обучается на людях Aalto, синтетических людях на русском и английском и ботах, которые печатают те же тексты. Синтетика нужна, чтобы язык текста не стал признаком бота: в Aalto только английский. Когда наберутся свои участники, их выгрузка добавляется через `--own`.

## План сбора данных и обучения

**Сколько данных нужно**

| Что | Минимум | Хорошо | Зачем |
|---|---|---|---|
| Участники (люди) | 30 | 50–60 | меньше 30 — интервалы для EER и ROC-AUC шире ±0.05, сравнение моделей ничего не покажет |
| Сессий на участника | 3 в **разные дни** | 4–5 | шаблон по прошлым дням, проверка — на последнем дне |
| Попыток человека | 30 × 3 × 12 ≈ 1 100 | 50 × 4 × 12 ≈ 2 400 | ~50–110 тыс. нажатий |
| Реальные читеры, на каждый тип из `tools/cheat_scripts` | 30 попыток | 60+ | 6 типов → 200–400 попыток, 3–5 разных «настроек» на тип |
| «Другой человек под чужим кодом» | 10 пар | 20 пар | проверка биометрии на реальных самозванцах |
| Сгенерированные боты (`keyml/bots.py`) | столько, чтобы читеров было ~20–30% | | добирают редкие типы |

**Разбиение (фиксируется ДО обучения)**

1. **Отложенный тест:** 20% участников целиком, которых модель не видит вообще, и один тип читерства целиком (например, `replay`). Его открываем один раз в конце.
2. **Остальное:** 5-кратная кросс-валидация с разбиением по участникам (GroupKFold) для подбора гиперпараметров.
3. **Попытки из режима отладки** в датасет не входят (`--keep-debug` выключен по умолчанию).

**Как показать, что модель реально обучилась, а не запомнила шум**

1. **Бейзлайны:** константа (всегда «доля читеров»), случайный классификатор, одно правило-порог (например, «разброс интервалов меньше X»). Модель должна обыгрывать их по ROC-AUC и Brier с непересекающимися бутстреп-интервалами по участникам.
2. **Перестановочный тест:** перемешиваем метки, обучаем заново 100 раз. ROC-AUC должен упасть к 0.5, а настоящий результат — оказаться правее всех 100 перестановок (p < 0.01).
3. **Кривая обучения:** качество на отложенных участниках при обучении на 5, 10, 20, 30… участниках. Кривая растёт и выходит на плато — значит, данных хватает. Если ещё растёт — нужно больше людей.
4. **Кривые loss на train и validation по эпохам** (MLP, GRU): validation не уходит вверх, то есть нет переобучения.
5. **Перенос:** модель, обученная только на синтетике, против модели, обученной на реальных людях, на одном и том же отложенном тесте. Это показывает пользу реального датасета.
6. **Обобщение на неизвестный тип читерства** (leave-one-type-out) — уже есть в отчёте.
7. **Калибровка на отложенном тесте:** reliability diagram и ECE. Вероятность 30% должна означать примерно 30% читеров.

## Методы

### Признаки (`keyml/features.py`)

Для соседних нажатий: **hold** (сколько клавиша удерживается), **dd** (время от нажатия до нажатия = латентность биграммы), **ud** (от отпускания до следующего нажатия; если ud < 0, следующая клавиша нажата раньше, чем отпущена предыдущая, это «перекрытие» или rollover).

| Группа | Признаки | Зачем |
|---|---|---|
| распределения | среднее, std, CV, асимметрия, эксцесс, квантили hold и dd | боты часто дают слишком узкие или симметричные распределения |
| энтропия | энтропия гистограммы log-dd и log-hold | у ботов с постоянной задержкой она ≈ 0 |
| динамика | автокорреляция log-dd (лаг 1, 2), «гладкость» | у людей темп дрейфует, у ботов задержки независимы |
| **структура раскладки** | корреляция dd с популяционной сложностью биграммы, доля необъяснённой дисперсии | у человека переход «тем же пальцем» медленнее, чем чередование рук, а простой бот этого не знает |
| моторика | доля перекрытий, связь hold и dd, паузы на пробелах | |
| ошибки | доля Backspace | |
| таймер ОС | статистика Рэлея для сетки 10 / 15.6 мс | AutoHotkey и `Sleep` привязаны к тику системного таймера |

Популяционные таблицы (средние по биграммам и клавишам) строятся **только по обучающим людям внутри фолда**, иначе была бы утечка.

### Античит

- **Логистическая регрессия (numpy):** взвешенная BCE + L2, оптимизатор Adam, градиент `Xᵀ(p − y)/n + λw`. Её веса интерпретируемы, а сама модель используется на сервере онлайн.
- **MLP (numpy):** 39 → 32 → 16 → 1, ReLU, dropout, ручной backprop.
- **BiGRU (PyTorch):** ячейка GRU написана по формулам, без `nn.GRU`. На вход подаётся последовательность нажатий (7 чисел на нажатие). Модель видит порядок, а не только агрегаты.
- **Валидация:** stratified GroupKFold по пользователям и экземплярам ботов. Отдельно проверяется **обобщение на неизвестный тип бота** (leave-one-bot-type-out). Это главный реалистичный сценарий: читер придумает то, чего не было в обучении.
- **Метрики:** ROC-AUC, F1, TPR при FPR = 1% (сколько читеров ловим, если ложно блокируем только 1% людей), доля пойманных по каждому типу бота.

#### Вероятность читерства вместо «да/нет» (`keyml/models/calibration.py`)

Модель не выносит бинарный вердикт. Для каждой попытки она выдаёт **P(читер)** и **90% доверительный интервал**, например «12% (интервал 4–27%)».

1. **Байесовская логистическая регрессия, аппроксимация Лапласа.** Апостериорное распределение весов приближается гауссианой `w ~ N(w*, Σ)`, где `Σ = H⁻¹`, а `H = Σᵢ sᵢ pᵢ(1−pᵢ) xᵢxᵢᵀ + λnI` — гессиан минус логарифма апостериорной плотности. Логит новой попытки тогда распределён нормально: `z ~ N(w*ᵀx, xᵀΣx)`. Отсюда 90% интервал `σ(m ± 1.645·√v)`. Для попыток, непохожих на обучающие, дисперсия `xᵀΣx` больше, и интервал шире. Точечная оценка — медиана `σ(m)`, она всегда лежит внутри интервала.
2. **Калибровка Платта.** `p = σ(a·z + b)`, коэффициенты подбираются методом Ньютона на out-of-fold логитах (кросс-фиттинг, без утечки). Модель учится со взвешиванием классов, поэтому без калибровки её «вероятность» не совпадает с реальной частотой. Качество калибровки измеряется reliability diagram, Brier, log-loss и ECE.
3. **Сдвиг априорной вероятности по формуле Байеса.** Калибровка верна для доли читеров в обучающих данных π_data. На сайте читеров меньше, поэтому `logit p = logit p_data − logit π_data + logit π_site`. Значение π_site задаётся переменной `KT_CHEAT_PRIOR`, по умолчанию 5%.
4. **Проверка интервалов:** сравнение с непараметрическим бутстрепом (30 моделей на бутстреп-выборках пользователей и ботов) и проверка того, что ошибка растёт вместе с шириной интервала.

На сайте участник после каждого задания видит строку вида «вероятность читерства 3% (90% интервал 1–8%)». В базу пишется P (`bot_score`) и интервал (`flags.p_cheat_ci90`).

### Биометрическая верификация

- **Калибровочная фраза:** вектор фиксированной длины (hold каждой клавиши + dd и ud каждой биграммы), как в датасете CMU (Killourhy & Maxion, 2009). Шаблон пользователя строится по прошлым сессиям.
  - **Махаланобис:** обучающих повторов (10–20) меньше, чем размерность (88 для русской фразы, 127 для английской), поэтому ковариация берётся со сжатием `S = (1−α)Ŝ + α·diag(Ŝ)`, иначе матрица вырождена.
  - **Scaled Manhattan:** `Σ|xⱼ − μⱼ| / MADⱼ`.
- **Свободный текст:** сиамская BiGRU, обученная triplet loss с batch-hard майнингом. Проверяется на пользователях, которых **не было в обучении** (open-set).
- **Метрика:** EER, точка, где доля ложно принятых чужих равна доле ложно отвергнутых своих.

### Профилирование

- **Кластеризация стилей:** вектор пользователя = средние 8 интерпретируемых признаков → k-means++ и GMM (EM, диагональные ковариации) → выбор k по силуэту и BIC → визуализация через PCA. Кластеры сверяются с ответом анкеты «как вы печатаете» (ARI).
- **Слабые биграммы, эмпирический Байес** (`keyml/profile.py`). Иерархическая модель на log-латентностях:
  `x ~ N(θ_ub, σ²_b)`, `θ_ub ~ N(μ_b + s_u, τ²_b)`.
  Гиперпараметры μ, σ², τ² оцениваются по всем пользователям методом моментов. Апостериорное среднее
  `θ̂ = (n/σ²·x̄ + (μ+s)/τ²) / (n/σ² + 1/τ²)`
  при малом n «стягивает» оценку к популяции. Вероятность того, что биграмма действительно слабая: `P(θ > μ+s) = Φ((θ̂ − μ − s)/sd_post)`.
  Проверка: прогноз латентности на **следующей** сессии сравнивается с выборочным средним.
- **Адаптивные упражнения:** слова из частотного словаря взвешиваются по суммарной «слабости» своих биграмм и сэмплируются через softmax с температурой.

## Результаты

`reports/results.md` создаётся автоматически. **Сейчас он посчитан на синтетических пользователях** (`keyml/simulate.py`): это проверка, что пайплайн работает, а не научный результат. После сбора данных перезапустите `run_experiments.py --data ...`. Все таблицы и графики пересчитаются, а модель античита на сервере обновится (`collector/model/anticheat.json`).

О чём стоит написать в отчёте (выводы на синтетике это подтверждают, на реальных данных их надо перепроверить):

1. Простые боты (const, uniform, gauss, ahk) ловятся почти идеально. «Очеловеченный» бот, replay и особенно бот, знающий сложность биграмм, ловятся плохо. Это честное ограничение подхода.
2. Нелинейные модели (MLP, деревья) заметно лучше логистической регрессии на сложных ботах.
3. Эмпирический Байес выигрывает у выборочного среднего на редких биграммах (n = 1–3). На частых методы сходятся, как и предсказывает теория.
