# КлавоТрен: клавиатурный тренажёр с биометрическим ML-античитом и адаптивным профилированием

Учебный проект по курсу «Основы машинного обучения».

Тренажёр записывает, **когда нажата и отпущена каждая клавиша**. По этим таймингам решаются три задачи:

| Задача | Вопрос | Свои реализации | Бенчмарки (sklearn) |
|---|---|---|---|
| **Античит** | печатает человек или скрипт/бот? | логистическая регрессия и MLP (numpy, ручной backprop), BiGRU с вручную написанной GRU-ячейкой (PyTorch) | LogisticRegression, RandomForest, HistGradientBoosting |
| **Биометрия** | печатает владелец аккаунта или кто-то другой? | детектор Махаланобиса со shrinkage-ковариацией, Scaled Manhattan (numpy), сиамская BiGRU + triplet loss (PyTorch) | OneClassSVM, IsolationForest |
| **Профилирование** | какой у человека стиль печати и какие переходы между клавишами у него слабые? | k-means++ и GMM/EM (numpy), PCA через SVD, эмпирический Байес для биграмм | KMeans |

Метрики (ROC-AUC, EER, ARI, силуэт) и разбиения GroupKFold тоже написаны с нуля (`keyml/metrics.py`). В тестах они сверяются со sklearn.

```

  static/             интерфейс: index.html, app.js, style.css
  model/              обученный античит и prior биграмм (создаются скриптом экспериментов)

  keyboard.py         геометрия клавиатуры, раскладки ЙЦУКЕН/QWERTY, пальцы
  data.py             формат данных, склейка keydown/keyup, загрузка .db/.jsonl
  features.py         39 признаков попытки + последовательности для GRU + векторы для биометрии
  bots.py             генератор ботов 7 типов (негативный класс)
  simulate.py         синтетические люди (только для отладки, пока нет реальных данных)
  profile.py          эмпирический Байес для слабых биграмм + адаптивные упражнения
  metrics.py          метрики и GroupKFold
  models/linear.py    логистическая регрессия, MLP (numpy)
  models/unsupervised.py   k-means, GMM, PCA, Махаланобис, Scaled Manhattan
  models/seq_torch.py BiGRU-классификатор, сиамская сеть (PyTorch)
  experiments.py      все эксперименты
scripts/
  run_experiments.py  полный прогон, результат в reports/results.md + графики
  export_data.py      скачать собранные данные с сервера
tools/cheat_scripts/  скрипты, которыми добровольцы генерируют реальные читерские попытки
tests/                сквозные тесты
```

## Быстрый старт

```bash
pip install -r requirements.txt

# 1. тренажёр локально: http://localhost:8000 (режим читера: http://localhost:8000/?cheat=1)
python collector/server.py

# 2. эксперименты на синтетических пользователях (проверить, что всё работает)
python scripts/run_experiments.py --simulate 50

# 3. эксперименты на реальных данных
python scripts/run_experiments.py --data collector/data/keystrokes.db
#    или на выгрузке с сервера
python scripts/export_data.py https://LOGIN.pythonanywhere.com ТОКЕН
python scripts/run_experiments.py --data data/real_attempts.jsonl

# тесты
python -m pytest -q tests
```

Если PyTorch не установлен, флаг `--no-torch` пропускает нейросетевые эксперименты, остальное работает.

## Как собрать датасет

### 1. Развернуть тренажёр в интернете (бесплатно, ~15 минут)

Вариант **PythonAnywhere** (бесплатный аккаунт, диск постоянный, SQLite там не теряется):

1. Зарегистрироваться на pythonanywhere.com, в Bash-консоли выполнить `git clone <ваш репозиторий>` (или загрузить файлы через вкладку Files).
2. Web → Add a new web app → Manual configuration → Python 3.10+.
3. В WSGI-файле (ссылка на странице Web) заменить содержимое на:
   ```python
   import os, sys
   os.environ["KT_ADMIN_TOKEN"] = "придумайте-длинный-секрет"
   sys.path.insert(0, "/home/ЛОГИН/omo_project")
   from collector.server import application
   ```
4. Static files: URL `/` → не нужно, сервер отдаёт статику сам. Нажать Reload.
5. Ссылка для участников: `https://ЛОГИН.pythonanywhere.com`.

Альтернатива на время сбора: запустить `python collector/server.py` у себя и открыть доступ через `cloudflared tunnel --url http://localhost:8000`. Но тогда компьютер должен быть включён всё время сбора.

> Онлайн-античит на сервере использует numpy. На PythonAnywhere numpy уже установлен. Если numpy нет, сервер просто не показывает оценку «человек/бот», а данные собирает как обычно.

### 2. Протокол для участника

- **Анкета:** язык текстов, тип клавиатуры, слепая печать или нет, ведущая рука, часы за клавиатурой в день. Её ответы дают признаки для анализа кластеров и «истину» для проверки, совпадают ли кластеры с самооценкой.
- **Сессия (~6 минут):** калибровочная фраза ×10 (панграмма: «съешь же ещё этих мягких булок» / «the quick brown fox…»), затем 6 текстов из корпуса. Со второй сессии добавляется персональное упражнение под слабые биграммы.
- **3 сессии в разные дни.** Сервер не даст начать новую сессию раньше чем через 8 часов (`KT_MIN_GAP_HOURS`). Без этого оценка биометрии получится нечестной: в один день человек печатает слишком одинаково.
- Участник получает код вида `ABCD-EF23`, который хранится в браузере. С ним можно продолжить с другого устройства.
- **Мотивация:** таблица лидеров, рост скорости по сессиям, отчёт о слабых переходах.

**Сколько нужно:** минимум 30 человек, лучше 50+, по 3 сессии. Это 30 × 3 × 16 ≈ 1500 попыток и ~70 000 нажатий. Где искать участников: своя группа и поток, чаты других групп, знакомые. Попросите каждого переслать ссылку двум друзьям.

### 3. Реальные читерские данные (негативный класс)

Боты генерируются программно (`keyml/bots.py`, 7 типов), но реальные примеры ценнее. Попросите 5–10 добровольцев:

1. Открыть `…/?cheat=1`, выбрать тип читерства. Все попытки помечаются `mode=cheat`.
2. Запустить один из скриптов из `tools/cheat_scripts/` (AutoHotkey или `autotype.py` на pynput) с разными параметрами.
3. Отдельный ценный тип — `other_person`: человек печатает под **чужим** кодом. Это тест биометрии.

Такие события браузер помечает `isTrusted=true`, то есть отличить их от человеческих можно только по таймингам. Ради этого и нужен ML. События, созданные JavaScript (`isTrusted=false`), сервер ловит простым правилом.

### 4. Этика и данные

- Согласие обязательно, иначе сервер не регистрирует участника. Имя не спрашивается, только псевдоним.
- Печатается только заданный текст, поэтому личной информации в записях нет.
- Тайминги нажатий относятся к биометрическим данным: в отчёте указать, что данные анонимны и используются только в учебных целях. Выгрузка доступна только по секретному токену.

### Формат данных

Каждая попытка (строка `.jsonl` / запись в SQLite):

```json
{"user_id": "ABCD-EF23", "session_no": 2, "kind": "calib|text|adaptive", "lang": "ru",
 "prompt": "...", "typed": "...", "mode": "normal|cheat", "cheat_type": null,
 "events": [["d", "KeyF", "а", 1532.4, 1], ["u", "KeyF", "а", 1621.0, 1], ...],
 "flags": {"blur": 0, "paste": 0, "user_meta": {...}}}
```

`events`: тип (`d` = keydown, `u` = keyup), физический код клавиши (`event.code`, не зависит от раскладки), символ, время в мс от показа задания (`performance.now()`), `isTrusted`.

## Методы

### Признаки (`keyml/features.py`)

Для соседних нажатий: **hold** (сколько клавиша удерживается), **dd** (время от нажатия до нажатия = латентность биграммы), **ud** (от отпускания до следующего нажатия; если ud < 0, следующая клавиша нажата раньше, чем отпущена предыдущая, это «перекрытие» или rollover).

| Группа | Признаки | Зачем |
|---|---|---|
| распределения | среднее, std, CV, асимметрия, эксцесс, квантили hold и dd | боты часто дают слишком узкие или симметричные распределения |
| энтропия | энтропия гистограммы log-dd и log-hold | у ботов с постоянной задержкой она ≈ 0 |
| динамика | автокорреляция log-dd (лаг 1, 2), «гладкость» | у людей темп дрейфует, у ботов задержки независимы |
| **структура раскладки** | корреляция dd с популяционной сложностью биграммы, доля необъяснённой дисперсии | у человека переход «тем же пальцем» медленнее, чем чередование рук, а простой бот этого не знает |
| моторика | доля перекрытий, связь hold и dd, паузы на пробелах | |
| ошибки | доля Backspace | |
| таймер ОС | статистика Рэлея для сетки 10 / 15.6 мс | AutoHotkey и `Sleep` привязаны к тику системного таймера |

Популяционные таблицы (средние по биграммам и клавишам) строятся **только по обучающим людям внутри фолда**, иначе была бы утечка.

### Античит

- **Логистическая регрессия (numpy):** взвешенная BCE + L2, оптимизатор Adam, градиент `Xᵀ(p − y)/n + λw`. Её веса интерпретируемы, а сама модель используется на сервере онлайн.
- **MLP (numpy):** 39 → 32 → 16 → 1, ReLU, dropout, ручной backprop.
- **BiGRU (PyTorch):** ячейка GRU написана по формулам, без `nn.GRU`. На вход подаётся последовательность нажатий (7 чисел на нажатие). Модель видит порядок, а не только агрегаты.
- **Валидация:** stratified GroupKFold по пользователям и экземплярам ботов. Отдельно проверяется **обобщение на неизвестный тип бота** (leave-one-bot-type-out). Это главный реалистичный сценарий: читер придумает то, чего не было в обучении.
- **Метрики:** ROC-AUC, F1, TPR при FPR = 1% (сколько читеров ловим, если ложно блокируем только 1% людей), доля пойманных по каждому типу бота.

### Биометрическая верификация

- **Калибровочная фраза:** вектор фиксированной длины (hold каждой клавиши + dd и ud каждой биграммы), как в датасете CMU (Killourhy & Maxion, 2009). Шаблон пользователя строится по прошлым сессиям.
  - **Махаланобис:** обучающих повторов (10–20) меньше, чем размерность (88 для русской фразы, 127 для английской), поэтому ковариация берётся со сжатием `S = (1−α)Ŝ + α·diag(Ŝ)`, иначе матрица вырождена.
  - **Scaled Manhattan:** `Σ|xⱼ − μⱼ| / MADⱼ`.
- **Свободный текст:** сиамская BiGRU, обученная triplet loss с batch-hard майнингом. Проверяется на пользователях, которых **не было в обучении** (open-set).
- **Метрика:** EER, точка, где доля ложно принятых чужих равна доле ложно отвергнутых своих.

### Профилирование

- **Кластеризация стилей:** вектор пользователя = средние 8 интерпретируемых признаков → k-means++ и GMM (EM, диагональные ковариации) → выбор k по силуэту и BIC → визуализация через PCA. Кластеры сверяются с ответом анкеты «как вы печатаете» (ARI).
- **Слабые биграммы, эмпирический Байес** (`keyml/profile.py`). Иерархическая модель на log-латентностях:
  `x ~ N(θ_ub, σ²_b)`, `θ_ub ~ N(μ_b + s_u, τ²_b)`.
  Гиперпараметры μ, σ², τ² оцениваются по всем пользователям методом моментов. Апостериорное среднее
  `θ̂ = (n/σ²·x̄ + (μ+s)/τ²) / (n/σ² + 1/τ²)`
  при малом n «стягивает» оценку к популяции. Вероятность того, что биграмма действительно слабая: `P(θ > μ+s) = Φ((θ̂ − μ − s)/sd_post)`.
  Проверка: прогноз латентности на **следующей** сессии сравнивается с выборочным средним.
- **Адаптивные упражнения:** слова из частотного словаря взвешиваются по суммарной «слабости» своих биграмм и сэмплируются через softmax с температурой.

## Результаты

`reports/results.md` создаётся автоматически. **Сейчас он посчитан на синтетических пользователях** (`keyml/simulate.py`): это проверка, что пайплайн работает, а не научный результат. После сбора данных перезапустите `run_experiments.py --data ...`. Все таблицы и графики пересчитаются, а модель античита на сервере обновится (`collector/model/anticheat.json`).

О чём стоит написать в отчёте (выводы на синтетике это подтверждают, на реальных данных их надо перепроверить):

1. Простые боты (const, uniform, gauss, ahk) ловятся почти идеально. «Очеловеченный» бот, replay и особенно бот, знающий сложность биграмм, ловятся плохо. Это честное ограничение подхода.
2. Нелинейные модели (MLP, деревья) заметно лучше логистической регрессии на сложных ботах.
3. Эмпирический Байес выигрывает у выборочного среднего на редких биграммах (n = 1–3). На частых методы сходятся, как и предсказывает теория.
